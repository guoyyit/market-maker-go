# 确定性回放

在**固定随机种子**（`RNGSeed`）与**相同输入事件序列**下，引擎产出的
报价、撤单与持仓变化序列逐条一致，可用于复现历史场景与回归测试。

## 确定性来自哪里

- **单 goroutine 状态机**：所有输入经一个通道串行处理，不存在数据竞争下
  的不确定交错（测试在 `-race` 下通过）。
- **整数价位/数量**：无浮点误差。
  数量倾斜同样全程整数运算（先乘后除、向 0 截断），不引入任何平台相关行为。
- **固定随机源**：PCG，种子来自配置；抖动只在新行情帧抽取，抽取计数持久化。
- **固定动作顺序**：先撤后挂，各自按 `ClientOrderID` 升序。
- **固定输出顺序**：意图内报价顺序固定为买侧档位升序、再卖侧档位升序；
  观测中的在挂快照按 ID 升序。
- **注入式时钟**：心跳判定时刻由 `TimerEvent.Now` 与行情帧时间决定，
  回放不依赖墙钟；`engine.Options.Now` 也可注入固定时钟。
- **本地撮合**：成交由内存网关的 `SimulateFill` 按在挂单确定性产生，
  不访问网络或外部服务。

## 输入序列

引擎接受四类事件，按注入顺序逐条处理：

- `TickEvent`：行情帧；
- `TradeEvent`：成交回报；
- `ConfigEvent`：热更新配置；
- `TimerEvent`：心跳检查点。

## 使用回放

`internal/replay` 提供记录与比对：

```go
rec := replay.NewRecorder()
err := replay.Run(ctx, eng, events, rec)

// 另一份完全相同的环境（新网关、空存储、同种子配置）再跑一次：
rec2 := /* ... */
ok := rec.Equal(rec2) // 逐条比较持仓、风险状态、流转、在挂报价
```

每条 `Step` 记录：事件序号、持仓、风控状态、是否被乱序/重复忽略、
本事件触发的保护流转，以及在挂报价的 `ID@价格x数量` 列表。

若场景包含本地撮合，可先用 `gw.SimulateFill(...)` 生成成交回报、
再把该回报包成 `TradeEvent` 注入，并用 `replay.StepFromObs` 记录该观测，
从而保证两次运行的成交也完全对齐。

`TestDeterministicReplay` 是端到端示例：同一脚本在两个独立目录各跑一次，
断言逐字节一致，并抽查成交补挂、重复忽略、超时空盘、热更新档位数等关键语义。

与成交到达顺序无关的保证由
`TestTradeSetResultIndependentOfArrivalOrder` 覆盖：同一组三笔不同成交的
**全部 6 种注入排列**产出相同的最终持仓（9）与逐单一致的在挂报价集合；
乱序成交在崩溃重启后仍只生效一次由
`TestOutOfOrderTradeAfterCrashAppliesOnce` 覆盖；
数量倾斜的正负偏离、归零停挂/自动恢复与系数热更新由
`internal/pricing` 与 `internal/engine` 下的 `TestQtySkew*` 覆盖。
这些测试均使用注入时钟与直接事件注入，不依赖真实时钟等待或固定睡眠。

## 复现历史

复现某段历史需要同时固定：初始/热更新配置（含种子）、全部事件（含时间戳
与序号）、以及本地撮合触发。持久化目录中的 `state.json` 与 `risk.log`
也可作为崩溃点之后继续重放的起点。
