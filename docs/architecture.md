# 架构与数据流

## 总览

```
            Tick / Trade / Config / Timer
                        │  (in-process channel)
                        ▼
                 ┌─────────────┐
                 │   Engine    │ 单 goroutine 状态机
                 └─────────────┘
        ┌───────────┬─────────┴───────────┬──────────────┐
        ▼           ▼                     ▼              ▼
   risk.Monitor pricing.Generator     ledger.Ledger   config.Manager
        │           │                     │
        │           ▼                     │
        │      book.Reconciler ──► gateway.InMemory ──► Fills chan
        ▼                                │
   risk.log (JSONL)                      ▼
                              store (state.json 原子快照)
```

全部组件都在同一进程内，网关为内存实现，不依赖任何外部服务。

## 单循环事件处理

引擎只有一个处理 goroutine：

1. 从输入通道取一条事件；
2. 分发到对应处理器，串行更新全部状态；
3. 需要时调整网关挂单并落盘；
4. 产出一条 `Observation`（持仓、风控状态、在挂报价、忽略/拒绝标记、
   本事件的保护流转）。

串行处理使"结果仅由输入序列决定"，无需在领域状态上加锁；
网关、账本、风控内部的锁仅用于构造/恢复阶段与外部只读查询。

## 各事件处理要点

### 行情 `TickEvent`

1. `Seq <= lastTickSeq` → 判定为重复或迟到旧帧，**忽略**（不覆盖任何状态）。
2. 交风控监视器判定：异常 → 记录流转、全量撤单、清空意图、持久化；
   正常（含从保护恢复）→ 更新最后有效行情。
3. `NORMAL` 下以最新行情与持仓生成意图，代号轮换后增量对账，成功则固化
   意图/代号/指纹并持久化。

### 成交 `TradeEvent`

1. 成交 `ID` 已在账本 → 重复回报，忽略。
2. `Seq <= lastTradeSeq` → 迟到回报，忽略（ID 去重先于序号判定）。
3. 账本入账更新持仓；被成交档位代号加 1。
4. `NORMAL` 且有行情时立即重新对账（用新代号补挂、套用倾斜与上限裁剪），
   再持久化。

### 配置 `ConfigEvent`

校验 → 原子替换三处参数 → 立即对账 → 持久化；非法配置返回拒绝标记，
不影响在挂报价。

### 定时器 `TimerEvent`

只做心跳检查；超时则记录流转、全量撤单、清空意图、持久化。

## 容错与一致性保证汇总

- 旧行情不覆盖新状态（序号水位）。
- 重复/迟到成交不重复影响持仓（成交 ID 幂等 + 序号水位），结果与顺序无关。
- 任何时刻对账完成后，网关在挂集合等于最近意图。
- 异常行情先全撤、再进入保护，恢复前不挂新单；流转全程审计。
- 持仓、意图、风控、代号/随机流、配置均持久化，重启不重复挂单、不丢意图，
  持仓恒等于成交重算结果。
- 固定种子与相同输入下输出逐条一致。
