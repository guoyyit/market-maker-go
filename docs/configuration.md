# 配置项与热更新

配置是一份**不可变快照** `config.Config`。引擎持有当前快照，
更新采用「整份替换 + 校验」，绝不允许读到半更新的参数组合。

## 配置项

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| `Symbol` | 做市标的 | 非空；单引擎服务单标的 |
| `Levels` | 每侧挂单档位数 | `>= 1` |
| `BaseQty` | 每档挂单数量 | `> 0` |
| `HalfSpread` | 最优档相对中间价的半价差 | `> 0` |
| `LevelStep` | 相邻档位价格间距 | `> 0` |
| `MaxSpread` | 允许的最大行情价差 | `> 0`，且 `2*HalfSpread <= MaxSpread` |
| `MaxPosition` | 持仓绝对值上限 | `>= 0` |
| `InventoryTarget` | 目标库存 | 任意整数 |
| `SkewCoeff` | 库存倾斜系数（价位） | `>= 0` |
| `SkewDenom` | 倾斜的库存分母 | `> 0` |
| `HeartbeatTimeout` | 行情心跳超时 | `> 0` |
| `MaxPriceJump` | 单笔中间价跳变阈值 | `> 0` |
| `JitterTicks` | 报价抖动上限 | `>= 0`，0 关闭 |
| `RNGSeed` | 确定性随机种子 | 任意整数 |

价格类字段单位为最小价位，数量类为最小数量单位，时长为 `time.Duration`。

## 热更新方式

通过 `ConfigEvent` 注入一份新配置：

1. **先校验**：校验失败则整个更新被拒绝，旧配置继续生效。
   观测结果中 `ConfigRejected=true` 且给出原因，引擎循环不受影响。
2. **原子替换**：校验通过后同时同步三处：
   - 配置管理器快照；
   - 报价生成器参数；
   - 风控监视器阈值（`SetParams`，不改变当前状态与行情基准）。
3. **立即对账**：若当前为 `NORMAL` 且已有有效行情，立刻以新参数生成意图，
   并与在挂集合做一次全量增量对账；否则等下一帧正常行情再生效。
4. **持久化**：生效后的配置写入 `state.json`，重启后继续使用。

## 对在途（已挂）报价的生效语义（确定性）

- **档位数 `Levels` 增加**：新增档位以代号 0 挂出，既有档位价格数量不变则
  不动作。
- **档位数减少**：消失档位立即撤销。
- **报价数量 `BaseQty` 变化**：所有保留档位数量改变 → 撤旧代号、挂新代号。
- **价差/步距 `HalfSpread/LevelStep`、倾斜 `SkewCoeff/SkewDenom/InventoryTarget`
  变化**：保留档位价格改变 → 撤旧代号、挂新代号。
- **`MaxPosition` 变化**：若新上限使当前持仓触及某侧上限，该侧立即撤掉；
  回落恢复后再挂回。
- **风控阈值变化**：只影响后续判定，不追溯已经在挂的单；若引擎当前处于
  `PROTECTED`，保持空盘直到正常行情出现。
- **`RNGSeed` 变化**：种子**不会**重置随机流。热更新不改变 RNGSeed 的语义，
  以保证抖动序列连续、回放确定；需要不同随机序列应通过新引擎实例
  （不同种子）获得。

所有对账动作仍遵循「先撤后挂、按 ID 升序」，因此在途报价的迁移结果
完全由旧在挂集合与新配置决定，可重复复现。
